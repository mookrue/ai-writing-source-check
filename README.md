# AI 文字與文獻快檢

協助作者檢查寫作品質、引用、證據與 AI 輔助研究流程的可重複工作規範。

本專案不是 AI 偵測器，也不會判定文章由誰撰寫。它把幾個容易混淆的問題分開處理：

- 文字是否空泛、公式化、缺乏具體證據或論證連結；
- 引用來源是否存在，書目資訊是否正確；
- 來源是否真的支持文中的主張；
- 資料品質、來源選擇與研究方法是否適合；
- AI 參與研究流程時，是否保留必要的人類判斷、驗證與紀錄。

## 我應該使用哪個版本？

| 你的情況 | 建議版本 | 從哪裡開始 |
|---|---|---|
| 不會安裝 Skill，只想上傳一個檔案 | Lite 直接上傳版 | [Lite 使用說明](docs/LITE_使用說明.md) |
| 平台支援原生 Agent Skills | 正式安裝版 | [`skill/check-ai-writing-and-sources/`](skill/check-ai-writing-and-sources/) |
| 想交給 Skill Creator 自動建立 | 完整規格版 | [`portable/AI文字與文獻快檢_完整規格版.md`](portable/AI文字與文獻快檢_完整規格版.md) |
| 想測試 Skill 是否真的有幫助 | A／B／C 測試 | [測試指南](docs/TESTING.md) |

第一次使用、也不確定平台支援什麼時，請選 **Lite 直接上傳版**。

## 最簡單的使用方法

1. 下載 [`AI文字與文獻快檢_Lite_直接上傳版.md`](portable/AI文字與文獻快檢_Lite_直接上傳版.md)。
2. 開啟一個新對話，把該檔案上傳給 AI。
3. 貼上下面這段話：

```text
請把附件《AI文字與文獻快檢 Lite》當成本次對話的檢查規則，不要摘要附件。
請先說明你這次實際能使用哪些搜尋、全文或資料庫工具，以及不能可靠判斷什麼；然後等我上傳文件。
```

4. 上傳自己的文件，說明要檢查哪一類問題。例如：

```text
請快速檢查這份文件的引用問題。請分開判斷來源存在、書目資訊與主張支持；查不到時不要直接判定虛構。
```

完整步驟、常用指令與故障排除請見 [Lite 使用說明](docs/LITE_使用說明.md)。

## 三種版本的差別

### 1. 正式安裝版

正式版本位於 `skill/check-ai-writing-and-sources/`，包含：

- 精簡的核心 `SKILL.md`；
- 按需載入的寫作、來源、方法與 AI 研究流程規範；
- 臺灣與中文來源查證路徑；
- 測試案例；
- DOI、ISBN 與網址候選擷取腳本。

它能依任務只載入需要的參考檔，最接近原作者使用中的版本。

### 2. Lite 直接上傳版

Lite 是給不能安裝 Skill 的使用者。它把必要底線、四條任務路由與基本輸出格式濃縮在單一 Markdown 檔。

優點是容易使用；限制是沒有原生 Skill 的自動觸發、按需載入、完整案例與可執行腳本。因此不能保證與正式版逐字或逐項相同。

### 3. 完整規格版

完整規格版由正式 Skill 自動產生，保留各檔案內容，適合：

- 公開審查規則；
- 跨平台移植；
- 交給 Skill Creator 重建資料夾；
- 在無法傳送資料夾時作為單檔備份。

它很長，不建議每次一般檢查都直接載入。

## 本工具不會做什麼

- 不輸出 AI 生成機率或作者判定。
- 不以流暢、套語或標點判定學術不端。
- 不把搜尋不到的中文文獻直接判定為虛構。
- 不把 DOI 可以開啟當成來源支持正文主張。
- 不聲稱進入實際無權限的付費資料庫。
- 不因多個 AI 給出相同答案，就把答案當成獨立驗證。
- 不預設重寫整篇文章或協助規避偵測。

## 能力取決於使用平台

Skill 或 Markdown 文件只規定工作流程，不會自動增加 AI 的資料庫權限。實際結果仍取決於：

- 能否讀取 PDF、Word、圖片及註腳；
- 是否有公開網路搜尋；
- 是否連接學術資料庫或機構資源；
- 是否能取得摘要、相關段落或全文；
- 文件的 OCR 品質與檔案大小限制。

因此，可靠的回答應清楚說明本次實際查過什麼，以及哪些項目仍是「尚未核實」。

## 上傳到 GitHub

1. 在 GitHub 建立新的 Repository。
2. 解壓縮下載套件。
3. 將解壓後的所有檔案與資料夾上傳到 Repository 根目錄。
4. 確認 GitHub 首頁能顯示本 `README.md`。

不需要開啟 GitHub Pages。Pages 是發布網站用的；這個專案直接使用 Repository 即可分享、下載與檢視。
